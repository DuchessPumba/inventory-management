Factory Inventory Management System

A full-stack demo: a Vue 3 single-page app talking to a FastAPI service that serves in-memory data loaded from JSON files. There is no database.

System architecture

Two processes on localhost, one data layer inside the backend.

Data flow

How a filter change on the dashboard becomes new numbers on screen.

  1. Filter state. useFilters holds four shared refs: period, warehouse (location), category and status. Every view reads the same state.
  2. Request. Views call getCurrentFilters() and pass the result to api.js. Values of all are dropped, and the period is sent as month (a month such as 2025-03 or a quarter such as Q1-2025).
  3. Filtering. The route handler runs apply_filters (warehouse, category, status) and filter_by_month (matches against order_date) over the in-memory lists.
  4. Validation. Pydantic models check the response shape before it is serialised.
  5. Rendering. The view keeps the raw response in refs and derives totals, chart series and table rows in computed properties.

Known gaps

Client methods without backend routes. api.js defines /tasks (GET, POST, PATCH, DELETE) and /purchase-orders (POST, GET). main.py has no routes for them, although it defines the Pydantic models PurchaseOrder and CreatePurchaseOrderRequest and reads purchase_orders to flag backlog items. No view or modal calls these methods today, so nothing breaks, but they would return 404 if used.
Two inconsistencies in the frontend. Reports.vue calls axios directly with a hardcoded http://localhost:8001 URL instead of going through api.js. Backlog.vue exists but has no route in main.js; the backlog is shown inside the Dashboard.
